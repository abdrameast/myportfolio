Le problème : un stock qui vit dans des fichiers Excel

Suivre du matériel technique réparti sur plusieurs projets, plusieurs magasins et plusieurs équipes est un exercice où le tableur atteint vite ses limites : pas d'historique fiable, pas de seuils d'alerte, pas de traçabilité, et des bons de livraison ressaisis à la main.

SysTrack répond à ce besoin par un catalogue d'équipements global dont le stock est suivi projet par projet : deux projets partagent la même fiche produit, mais disposent de quantités, de seuils, de kits et d'historiques totalement indépendants. Chaque mouvement — retrait, retour, ajustement, RMA — est transactionnel et historisé (utilisateur, date, quantité, motif, IP, navigateur).

Ce que fait SysTrack au quotidien

Stock suivi par projet

Catalogue d'équipements global, quantités et seuils par projet. Un sélecteur global pilote l'ensemble de l'application : équipements, tableau de bord, panier, kits, historique.

Authentification OIDC & RBAC

Connexion par redirection Logto (SSO), jeton vérifié côté serveur, provisionnement automatique du compte. Trois rôles : ADMIN, MANAGER, USER — ce dernier limité à ses projets.

Bons de livraison & de retrait

Génération automatique de documents Excel au modèle de l'entreprise, numérotation séquentielle commune BL / BR, préfixe paramétrable, modèle personnalisable et historique re-téléchargeable.

Préparations & kits métier

Préparation de commande ligne par ligne avec indicateur d'avancement, et kits métier propres au projet, dépliables en un clic et duplicables d'un projet à l'autre.

QR codes & scan caméra

Chaque équipement porte un code interne, un code-barres et un QR code généré, lisibles à la caméra depuis un mobile pour ouvrir la fiche et enchaîner un mouvement.

Tableau de bord & audit

Widgets temps réel, évolution des mouvements sur 14 jours, répartition par catégorie, alertes de stock — et un journal d'audit couvrant chaque action de chaque utilisateur.

Extrait de code

Un retrait de stock transactionnel

Décrémenter le stock, écrire le mouvement et tracer l'action doivent réussir ou échouer ensemble : la transaction Prisma garantit qu'aucun stock ne peut diverger de son historique.

stock.service.ts 
// Retrait de stock — atomique : stock, mouvement et audit ou rien.
async withdraw(dto: WithdrawDto, ctx: AuthContext) {
  return prisma.$transaction(async (tx) => {

    // 1. Le stock est porté par le couple (équipement, projet)
    const stock = await tx.equipmentStock.findUniqueOrThrow({
      where: { equipmentId_projectId: { equipmentId: dto.equipmentId, projectId: ctx.projectId } },
    });

    if (stock.quantity < dto.quantity) {
      throw new AppError('Stock insuffisant', 409);
    }

    // 2. Décrément puis historisation du mouvement
    await tx.equipmentStock.update({
      where: { id: stock.id },
      data: { quantity: { decrement: dto.quantity } },
    });

    const movement = await tx.movement.create({
      data: { type: 'WITHDRAWAL', quantity: dto.quantity, reason: dto.reason,
              equipmentId: dto.equipmentId, projectId: ctx.projectId, userId: ctx.userId },
    });

    // 3. Journal d'audit : qui, quoi, quand, depuis où
    await auditRepository.log(tx, { action: 'WITHDRAWAL', ctx, target: movement.id });

    return movement;
  });
}

Défis techniques relevés

01

Un catalogue global, des stocks cloisonnés

Modéliser une référence unique partagée par plusieurs projets tout en gardant des quantités, seuils, kits et historiques indépendants : une table EquipmentStock pivot, et un périmètre projet propagé du sélecteur global jusqu'aux requêtes SQL.

02

Intégrité des mouvements de stock

Chaque retrait ou retour touche trois tables. Les transactions Prisma garantissent l'atomicité, et les contrôles métier (stock disponible, motif obligatoire, statut de l'équipement) sont centralisés dans la couche service, jamais dupliqués dans les contrôleurs.

03

Génération de documents au modèle de l'entreprise

Produire un Bon de Livraison Excel qui reste strictement conforme au gabarit interne — feuille de paramètres, références nommées, logo conservé — tout en injectant un tableau d'articles de taille variable et une numérotation séquentielle partagée entre BL et BR.

04

Authentification déléguée, prête pour le SSO

Reproduire le flux OIDC complet avec un Logto auto-hébergé en développement, tout en gardant la possibilité de pointer vers le SSO d'entreprise en production sans changer une ligne de code — seulement des variables d'environnement.

05

Une interface qui tient sur le terrain

PWA installable, mode sombre/clair, squelettes de chargement, recherche instantanée, tri multi-colonnes et pagination serveur : l'application doit rester utilisable en magasin, sur mobile, une main occupée par le matériel.

Et MiniTrack, comment est-ce fait ?

La démo ci-dessus n'est ni une vidéo, ni une iframe, ni un build React embarqué : c'est une application écrite en JavaScript vanilla, sans dépendance, sans réseau et sans stockage. Le jeu de données est scripté en dur et l'historique de mouvements est généré par un générateur pseudo-aléatoire déterministe, pour que les graphiques soient crédibles et identiques à chaque visite.
